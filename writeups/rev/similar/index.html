Vulnerability & Code Analysis

배포 파일은 stripped PIE 바이너리 하나다.

실행하면 /dev/urandom으로 시드를 잡아 랜덤 3차원 벡터 30개를 뿌리고, 어떤 순서를 요구한다.

main

원소는 {int x, int y, int z, int index} 16바이트 구조체다. 벡터 성분만 출력되고 index는 출력되지 않지만, 처음에는 index == i이므로 i번째 줄의 벡터가 index i를 들고 있다는 걸 알 수 있다.

요구되는 입력은 compar 기준으로 정렬한 뒤의 index 나열이다. 시드가 /dev/urandom이라 랜덤 예측은 불가능하고, 30!가지 순서를 때려 맞출 수도 없다. 결국 compar를 그대로 재현하는 게 유일한 길이다.

alarm(60)이 걸려 있어 수동 입력으로는 시간이 빡빡하다.

정렬 키: sub_16A3 (0x16A3)

compar가 각 원소마다 부르는 헬퍼다. 디컴파일이 지저분해서 어셈블리로 보는 게 빠르다.

.rodata에서 상수 두 개를 확인할 수 있다.

정리하면 고정 벡터 (1, 1, 1)과의 코사인 거리다.

문제 이름 similar가 cosine similarity를 가리킨다.

compar (0x17C8) — -1을 안 돌려주는 비교 함수

C로 옮기면 이렇다.

-1 경로는 fa - fb >= 1e-7, 즉 fa > fb일 때만 도달하는데 그 조건에서는 항상 fb <= fa라 jbe가 먹힌다. 결과적으로 이 비교 함수는 0과 1만 돌려준다.

처음엔 이게 함정이라고 생각했지만, glibc qsort는 비교 결과가 > 0인지만 보고 원소를 뒤로 미는 구조다. 음수와 0을 구분하지 않으므로

  • 0 = “a가 b보다 작거나 같다”
  • 1 = “a가 b보다 크다”

로 완전히 일관된 순서가 되고, 결과는 f 오름차순 정렬과 같다.

1e-7은 동일 키 허용 오차다. 랜덤 값에서 1e-7 이내로 붙는 경우는 사실상 방향이 완전히 같은 벡터(예: (1,2,3)과 (3,2,1) 같은 성분 순열, 또는 (1,2,3)과 (2,4,6) 같은 스칼라배)뿐이고, 그때는 안정 정렬 순서가 정답이 된다. Python sorted가 stable이라 그대로 맞는다.

취약점

취약점이라기보다 정렬 키를 복원하는 문제다. 랜덤 시드는 /dev/urandom에서 와서 예측할 수 없지만, 값이 전부 출력되기 때문에 비교 함수만 재현하면 매 라운드 정답을 바로 계산할 수 있다. 브루트포스는 필요 없다.

Exploit / Solver Strategy

  1. Values: 이후 30줄을 파싱해 index -> (x, y, z) 매핑을 만든다.
  2. 각 벡터의 키 1 - (x+y+z) / (sqrt(x²+y²+z²) · sqrt(3))를 계산한다.
  3. 키 오름차순으로 stable sort 하고, 그 순서대로 원래 index를 출력한다.
  4. Result? 다음에 index 30개를 개행으로 구분해 보낸다.

(0,0,0)이 나오면 nb = 0이라 0 나눗셈으로 NaN이 된다. comisd는 unordered일 때 CF/ZF를 모두 세워 양쪽 jbe가 다 먹히므로 compar는 1(= 항상 큼)을 돌려준다. 솔버에서도 키를 inf로 둬서 맨 뒤로 보냈다. 확률은 1/8,000,000 수준이라 실제로 볼 일은 없다.

Final Payload or Solver

로컬 바이너리로 60회 연속 돌려 60/60 성공을 확인한 뒤 원격에 붙였다.

cat flag

플래그 본문에 c0s1n3이 들어 있어 의도된 풀이가 코사인 유사도 정렬이었음을 확인할 수 있다.
