Vulnerability & Code Analysis

배포 파일은 stripped PIE 바이너리 prob와 Dockerfile이다. Dockerfile을 보면 socat으로 포트 31337에 그대로 물려 둔 원격 문제고, flag는 작업 디렉터리의 ./flag에서 읽는다.

실행하면 프로그램을 입력받는다.

main (0x151D)

init(0x12EA)에서 alarm(5)를 걸고, SIGALRM 핸들러(0x12C9)는 "Machine Time Ended"를 찍고 exit(-1)한다. 즉 5초 안에 끝나야 한다.

vm (0x136D)

리턴값이 “실행한 명령어 개수”다. 즉 8바이트짜리 프로그램으로 10만 스텝 이상 돌린 뒤 정상 종료시키는 게 목표다.

디스패치는 두 단계다.

점프 테이블(0x2020, int32 상대 오프셋 18개)을 풀면 실제로 구현된 건 5개뿐이다.

ISA

명령 주소 동작
+ 0x13ED mem[dp]++ (u8)
- 0x141A mem[dp]-- (u8)
l 0x146D dp--, 0 미만이면 0으로 clamp
r 0x1492 dp++, 7 초과면 7로 clamp
n 0x14DA nop
a 0x1447 mem[dp] != 0 이면 pc = 0 (증가 없이), 0이면 다음 명령으로
e 0x14B8 halt → 스텝 수 리턴

pc도 7에서 clamp된다(0x14F9). 그래서 halt 없이 끝까지 가면 prog[7]을 무한 반복하다 alarm에 걸린다.

취약점

점프 명령이 a 하나뿐이고 그 목적지가 항상 프로그램 맨 앞(pc = 0) 이다. 겉보기엔 단순 while 하나만 가능해 보이지만,

  • a는 셀이 0일 때 아래로 흘러간다
  • 뒤쪽에 a를 하나 더 두고 다른 셀을 보게 하면, 그 두 번째 a가 바깥 루프가 된다
  • 바깥 루프가 pc = 0으로 돌아갈 때 dp는 그대로 남아 있으므로, 맨 앞에서 l로 dp를 되돌려 주면 안쪽 루프가 다시 첫 셀을 보게 된다

이걸로 8바이트 안에 2중 루프가 만들어진다. 셀이 u8이라 0 - 1 = 255가 되어 카운터 초기화도 - 한 번으로 끝난다.

Exploit / Solver Strategy

  • 안쪽 루프 한 바퀴 = l, -, a 3스텝, mem[0]이 0이 될 때까지 256회 → 768스텝
  • 그 뒤 r, -, a 3스텝 → 바깥 루프 한 바퀴 771스텝
  • mem[1]도 256회 → 256 * 771 + 1(e) = 197377

197377 > 99999로 조건을 넘고, 20만 스텝은 네이티브 속도라 alarm(5)에 걸리지 않는다. 입력은 7바이트지만 read(0, prog, 8) 안에 들어가고, e에서 멈추므로 8번째 바이트(개행)는 실행되지 않는다.

Final Payload or Solver

cat flag

시뮬레이터가 계산한 스텝 수와 바이너리가 출력한 Result가 정확히 일치한다.

로컬에서 먼저 돌려 볼 때는 ./flag를 직접 만들어 두고 p = process("./prob") 쪽 주석을 바꿔 끼우면 된다.
