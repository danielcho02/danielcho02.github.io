Vulnerability & Code Analysis

배포 파일은 stripped PIE 바이너리 하나다.

13글자를 받아서 맞으면 flag를 읽어준다.

main

루프 본문에 분기도 백트래킹도 없다. 문자 하나당 테이블 조회 두 번, 변수 두 개 갱신으로 끝난다. 전형적인 DFA 구동 루프다.

테이블의 모양

인덱스 20 * v4 + 2 * j가 구조를 전부 알려준다. j는 앞의 선형 탐색에서 나온 값이라 0~9, 따라서 2 * j는 최대 18 — 한 상태가 차지하는 폭이 정확히 20 int다.

unk_4020과 dword_4024는 같은 배열을 4바이트 차이로 가리키는 별명이다. 행 개수는 심볼 간격에서 바로 나온다.

Aho–Corasick

이 자료구조는 여러 패턴을 한 번에 찾는 Aho–Corasick 자동자다. 패턴들을 트라이로 쌓아 각 노드를 상태로 삼고, 매칭이 어긋났을 때 “지금까지 읽은 것의 접미사”에 해당하는 상태로 점프하는 실패 링크를 미리 계산해 표에 녹여 넣는다. 그래서 실행 중에는 텍스트를 한 번만 훑으며 표만 따라가면 모든 패턴의 등장 여부가 나온다.

바이너리의 요소가 알고리즘의 요소와 1:1로 대응한다.

Aho–Corasick 바이너리
현재 상태 v4
goto: 상태 × 문자 → 상태 unk_4020[20*v4 + 2*j]
output: 패턴 번호 / 없음 dword_4024[...] / -1
찾은 패턴 집합 v5의 비트

패턴 복원

상태 0에서 BFS로 각 상태의 최단 도달 문자열을 구하면 트라이가 그대로 되살아난다. 출력을 내는 전이는 8개, 즉 패턴은 4개가 아니라 8개다.

노드 20개 + 루트 1개 = 21개 상태로 딱 맞는다. 표 마지막 행(0x4658부터 14h dup(0))은 어느 전이에서도 도달하지 않는 패딩이다.

여기서 조건의 진짜 의미가 드러난다. v5 == 15는 느슨한 v5 & 15 == 15가 아니다.

  • 비트 0~3 (this sisa answ werr) — 전부 등장해야 한다
  • 비트 4~7 (rawr thus sins asia) — 하나라도 등장하면 v5 > 15로 탈락

후자가 함정이다. 알파벳 aehinrstuw가 요구 패턴에 필요한 글자(a e h i n r s t w)에 u만 더한 구성인 것도 thus를 밟게 유도하려는 미끼다.

Exploit / Solver Strategy

길이 13, 알파벳 10글자면 10^13가지다. 전수조사는 불가능하다.

핵심은 프로그램이 기억하는 게 v4와 v5 둘뿐이라는 점이다. i번째 글자 이후의 판정은 그때까지 무엇을 썼는지와 무관하게 이 두 값만으로 결정된다. 그리고 가능한 조합은

이므로, 글자 수를 한 칸씩 늘려가며 도달 가능한 (v4, v5) 집합만 유지하면 된다. 같은 조합에 이르는 서로 다른 문자열은 이후 동작이 완전히 같으니 하나만 남기고 버린다. 탐색 공간이 10^13에서 수백 개로 줄어든다.

  1. ELF에서 0x4020부터 1680바이트를 읽어 goto / out 두 테이블로 분리한다.
  2. (0, 0)에서 시작해 13계층 BFS. 각 노드에 (직전 노드, 사용한 문자)를 기록한다.
  3. 13번째 계층에서 v5 == 15인 노드를 찾아 역추적해 문자열을 복원한다.

mask를 하위 4비트로 잘라 쓰지 않는 것만 지키면 함정 비트는 자동으로 걸러진다.

Final Payload or Solver

PIE라 ELF.read()가 이미지 베이스 0 기준으로 읽어주므로 주소를 그대로 쓰면 된다. 로컬 검증은 바이너리 실행 권한을 건드리지 않도록 로더를 경유했다.

정답은 thisisanswerr — 요구 패턴 4개가 한 글자씩 겹쳐 사슬처럼 이어진다. 13글자가 최소 길이인 이유가 여기 있다.

this의 s가 sisa의 시작이고, sisa의 a가 answ의 시작이며, answ의 w가 werr의 시작이다. 실패 링크 없이는 이런 겹침을 한 번의 스캔으로 잡아낼 수 없다. 문제가 Aho–Corasick을 고른 이유이자, 제목이 Aho인 이유다.
