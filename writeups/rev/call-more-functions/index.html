Vulnerability & Code Analysis

stripped x86-64 PIE main 하나가 주어진다. 눈에 띄는 문자열은 다음 두 개뿐이다.

main

입력 64글자가 검사를 통과하면 입력 그대로 DH{...} 안에 출력된다. 즉 통과하는 입력 자체가 flag다.

검사 함수 0x1311 = 작은 스택 VM

0x1311은 분기 없이 mov edi, imm + call이 수백 번 반복되는 함수다. 호출 대상은 네 개뿐이다. (전역 스택 0x50a0, 스택 포인터 0x508c, 실패 플래그 0x5088)

정리하면 다음과 같다.

0x1311은 마지막에 fail(0x5088)을 반환하고, 0이어야 Correct가 출력된다.

함수 끝부분을 보면 입력 바이트 여러 개를 load해서 xor로 모두 접은 뒤, 상수와 cmp하는 패턴이 반복된다.

load 64번, cmp 64번이 있으므로 64개 입력 바이트에 대한 XOR 등식 64개가 된다.

취약점

Exploit / Solver Strategy

손으로 수백 개 호출을 따라갈 필요 없이, objdump 출력에서 mov edi, imm와 call 대상만 순서대로 뽑으면 VM 명령 리스트가 된다.

load의 인덱스는 항상 바로 앞에서 push한 상수이므로 as_long()으로 바로 꺼낼 수 있다.

Final Payload or Solver

binutils(objdump), z3-solver가 필요하다.

cat flag

z3가 구한 입력을 실제 바이너리에 넣었을 때 Correct가 출력되어 정답을 확인했다.
