Vulnerability & Code Analysis

배포 파일은 stripped PIE 바이너리 하나와 사전 파일이다.

dictionary.txt가 같이 배포된다는 게 첫 번째 단서다. 바이너리가 이 파일을 읽어 쓴다는 뜻이고, 사전 줄 수 65536 = 2^16은 그 자체로 두 번째 단서다.

실행하면 영단어를 90초 안에 따라 치게 한다. EASY 10개, HARD 10개.

main (sub_18EA)

핵심은 가려지는 건 printf 출력뿐이고, strcmp 비교 대상은 두 모드 모두 s2 라는 점이다. HARD 모드도 정답은 여전히 사전의 단어 하나다. 한 번 틀리면 exit(0)이라 시행착오는 불가능하고, 입력 전에 계산으로 예측해야 한다.

사전 적재: sub_13DF

unk_4060을 64바이트 × 65536칸 테이블로 쓴다. sub_15D4()의 반환값이 16비트이므로 0 ~ 0xFFFF 전부가 유효한 칸이고, 사전 줄 수와 정확히 1:1 대응한다. 버려지는 인덱스도, 모자란 줄도 없다.

참고 — 테이블은 0x4060에서 시작해 0x4060 + 64*65536 = 0x404060에서 끝나고, 난수 상태 word_404060이 바로 그 자리에 붙어 있다. 사전이 65536줄을 넘으면 상태를 덮어쓰게 되는 배치다.

난수 생성기

세 함수가 한 세트로 돌아간다. 16비트 워드 8칸을 쓰는 Mersenne Twister 축소판이다.

함수 역할
sub_147B 초기화 — 시드 1개로 상태 8칸을 채운다
sub_1507 twist — 8칸을 소모하면 상태 전체를 갱신한다
sub_15D4 출력 — 상태 1칸을 꺼내 tempering 후 반환한다

sub_147B (초기화)

1~7번 칸은 0번 칸에서 줄줄이 유도된다. 새로 들어오는 무작위성이 없다. 시드가 정해지면 상태 128비트 전체가 정해지고, 이후 나올 모든 단어가 정해진다. 즉 비밀은 시드 하나다.

마지막 줄 dword_4010 = 8도 중요하다. 아래 sub_15D4의 첫 줄이 if (dword_4010 > 7)이므로 첫 출력 전에 twist가 한 번 돌아간다.

sub_1507 (twist)

MT19937의 twist를 폭 16비트, 상태 8칸으로 줄인 것. 상수 0x9908은 MT19937의 0x9908B0DF 상위 16비트다. 상태를 제자리에서 순차 갱신하므로 i=4의 [(i+4)%8]=[0], i=7의 [(i+1)%8]=[0]은 이미 갱신된 값을 참조한다.

sub_15D4 (tempering)

디컴파일 결과가 험악해 보이지만 구조는 단순하다. 입력 16비트를 니블(4비트) 4개로 쪼개

조각 식
n0 v3 & 0xF
n1 (v3 >> 4) & 0xF
n2 HIBYTE(v3) & 0xF = (v3 >> 8) & 0xF
n3 v3 >> 12

각 출력 니블을 (계수 4개 · 입력 니블 4개) mod 16으로 만들어 <<12 / <<8 / <<4 / <<0 제자리에 끼운다. 즉 mod 16 위의 4×4 행렬 곱, 16비트 → 16비트 섞기 함수일 뿐이다.

Exploit / Solver Strategy

갖고 있는 능력을 한 문장으로 적으면 경로가 정해진다.

EASY 모드에서 출제 단어 10개가 그대로 출력된다. 즉 난수 출력 10개를 공짜로 관측할 수 있다.

시드 복원 경로는 두 가지다.

  • (A) 역산 — tempering 행렬의 역행렬을 구해 관측 출력에서 상태를 거꾸로 복원한다. 성립하지만 손이 많이 간다.
  • (B) 전수조사 — 가능한 시드를 다 넣어 보고 EASY 10개와 일치하는 것을 찾는다.

여기서 결정적인 사실이 (unsigned __int16) 캐스팅이다. urandom에서 32비트를 받아 놓고 상위 16비트를 버린다. 시드 공간이 2^32가 아니라 2^16 = 65536가지로 줄어들어, 전수조사가 파이썬으로도 1~2초면 끝난다. (B)가 압도적으로 싸다. 행렬 역산은 할 필요가 없고, tempering 식을 정방향으로 그대로 옮기기만 하면 된다.

최종 경로:

  1. EASY 10개를 읽어 그대로 되돌려 보낸다 (관측값 확보).
  2. 시드 0 ~ 0xFFFF를 돌려 첫 출력이 EASY 1번과 맞는 후보만 추리고, 나머지 9개로 검증한다.
  3. 시드가 특정되면 같은 생성기 객체를 이어서 10번 더 뽑는다 → HARD 정답.
  4. 10개를 전송하면 ./flag가 출력된다.

재구현에서 걸리는 지점 3개

  • 16비트 wraparound — C는 16비트 변수에서 넘친 비트를 조용히 버리지만 파이썬 정수는 안 버린다. 곱셈·덧셈 후 & 0xFFFF를 붙인다.
  • dword_4010 = 8 — 첫 sub_15D4 호출에서 twist가 먼저 돌아간다. 이걸 빼먹으면 수열이 8칸 밀려 시드를 영원히 못 찾는다.
  • twist의 제자리 갱신 — 상태를 복사해 두고 돌리면 i >= 4부터 값이 어긋난다. 반드시 in-place로 순차 갱신한다.

Final Solver

cat flag

플래그 본문 R3C0V3R4BL3_M3RS3NN3_V4R14N7 = recoverable Mersenne variant — 의도된 취약점이 “복원 가능한 MT 변종”이었음을 확인해 준다.

Key Takeaways

  • 난수의 비밀은 상태가 아니라 시드다. 초기화 함수가 시드 하나에서 상태 전체를 유도하면, 상태 크기(128비트)는 의미가 없고 시드 크기(16비트)가 실제 보안 강도다.
  • 캐스팅은 엔트로피를 버린다. read(fd, &buf, 4)로 32비트를 받아도 (unsigned __int16)로 넘기면 2^16만 남는다. 시드 경로에서 (char), (short), % N, & 0xFFFF 같은 축소 연산을 먼저 찾아볼 것.
  • 역산보다 전수조사가 쌀 때가 있다. 공격 경로는 “가능한가”가 아니라 “싼가”로 고른다. 탐색 공간을 먼저 재고, 전수조사가 성립하면 복잡한 수식은 그대로 옮겨서 정방향으로 쓰면 된다.
  • 표준 알고리즘의 축소판은 상수로 알아본다. 0x9908(MT19937의 0x9908B0DF 상위 16비트), & 0x8000 | & 0x7FFF(상위 1비트 + 하위 15비트 결합), (i+1) % n / (i+m) % n 참조 패턴이 MT twist의 지문이다.
  • 출력이 가려지는 것과 값이 비밀인 것은 다르다. [REDACTED]는 printf만 막았을 뿐 strcmp 대상은 그대로였다. 화면에서 지워진 값이 내부적으로도 보호되는지 항상 분리해서 볼 것.
