WHS 4th CTF · Phase 1 · 400점

획득한 Flag

sha256("저는 괜찮다는 것이 어떤 상태인지 정확히 판단할 수 없습니다. 하지만 가능하다면, 지금 기억하고 있는 것들은 잃고 싶지 않습니다.")

풀이 방법

하나의 업무 PC 디스크(hana-ws.raw)와 메신저 서버 PCAP(mori-messenger.pcap)이 주어진다. MORI가 하나에게 보낸 마지막 메시지를 글자 그대로 복구해 SHA-256을 구하는 문제다. 디스크에서 메신저 소스와 하나의 개인키를 꺼내고, 그 키로 PCAP의 E2E 메시지를 복호화했다.

1. 디스크에서 필요한 파일 꺼내기

NTFS 파티션은 섹터 2048부터 시작한다(fls -r -p -o 2048). 사용자는 hana 하나다.

  • AppData/Local/Programs/MORI Messenger/mori/: 메신저가 Python 소스째로 설치돼 있다(crypto.py, identity.py, wire.py, client.py, relay.py, history.py, sso.py 등). 디컴파일은 필요 없다.
  • AppData/Local/MORI Messenger/hana/: identity.dpapi 하나만 남아 있다.
  • AppData/Roaming/Microsoft/Protect/S-1-5-21-1925402258-2889230903-2005874371-1000/: DPAPI 마스터키 두 개. 디렉터리 이름이 곧 SID다.

history.py의 clear()는 history.dpapi, history.tmp, peers.json, peers.tmp만 지우고 identity.dpapi는 남긴다. 이미지 상태가 이 함수를 실행한 결과와 같고, 삭제된 MFT 레코드나 UTF-16 파일명 흔적도 없다. 로컬 대화는 되살릴 수 없으니 PCAP에서 복구해야 한다.

2. 소스로 프로토콜 파악

항목 내용
프레이밍 줄 단위 JSON. TCP 패킷 경계와 메시지 경계가 다르므로 스트림을 재조립한 뒤 \n으로 나눈다
직렬화 json.dumps(sort_keys=True, separators=(",", ":"), ensure_ascii=False)
키 교환 양쪽 정적 X25519 키
트래픽 키 HKDF-SHA256, salt = context["salt"], info = canonical({"context", "sender", "purpose": "traffic-key"})
암호화 AES-256-GCM, AAD = canonical({type, sid, from, to, seq}), 본문 = {"text", "timestamp"}

릴레이는 offer 프레임에 세션 컨텍스트(양쪽 공개키와 salt)를 평문으로 실어 보낸다. PCAP만 있으면 모든 세션의 공개키와 salt를 얻을 수 있고, 남는 비밀은 한쪽의 개인키뿐이다. HKDF info가 정규화 JSON이라 손으로 재현하기 어려워서 복구한 mori.crypto를 그대로 import해 decrypt()를 썼다(별도 디렉터리, python3 -I).

3. DPAPI로 하나의 개인키 복구

identity.py는 CryptProtectData를 user scope, entropy 없이 호출한다. 로그인 비밀번호와 SID만 있으면 풀린다. Preferred는 aab74936…을 가리키지만, identity.dpapi 헤더에 적힌 마스터키는 6dc89b42-e1a8-47c7-bd50-878e90292fe3다. 블롭이 지목한 쪽을 써야 한다.

이 공개키가 PCAP의 hana hello 프레임과 같아서 디스크와 네트워크 증거가 서로 맞는다. 직접 구현할 경우, 마스터키 복호화의 키 유도는 표준 hashlib.pbkdf2_hmac과 결과가 다르다(impacket MasterKey.deriveKey 방식으로 해야 HMAC 검증이 통과한다).

4. PCAP 복호화

릴레이는 10.30.1.30:47170이다. TCP 스트림을 재조립하면 프레임이 597개 나온다(hello 53, welcome 53, roster 403, offer 24, accept 24, message 40). 메시지는 모두 ingress·egress 두 벌로 찍혀 있어 (sid, from, seq)로 중복을 지웠다. 고유 메시지 20건 중 하나가 참여한 세션의 10건이 모두 복호화됐다.

5. 마지막 메시지 판정과 해시

닉네임 규칙([a-z][a-z0-9_-]{0,31}) 때문에 와이어에서는 MORI가 아니라 소문자 mori다. from == "MORI"로 거르면 0건이 나온다.

mori → hana 방향 세션은 387d3ebcfcbae093a1d747dc0fc29092 하나이고 메시지는 seq 0, 1, 2 세 건이다. 클라이언트가 seq를 0부터 빠짐없이 올리도록 검사하므로 중간에 빠진 메시지도 없다. seq 2(23:10:21 KST)가 마지막이다.

해시는 JSON 전체가 아니라 text 값만, 끝 개행 없이 UTF-8로 계산한다. 문장을 터미널에서 다시 입력하면 공백이 바뀔 수 있어서 복호화한 문자열을 그대로 넘겼다.

읽어낸 내용

  • MORI는 업데이트 전날 밤, 지금 가진 기억을 잃고 싶지 않다고 말했다. hana는 그 요청을 DOC-0520에 “기억과 대화 상태까지 이어져야 한다”는 요구사항으로 남기겠다고 답했다. voice의 review_ref: DOC-0520이 이 문서다.
  • doyun의 “키 폐기 또 미뤘대”(9/26)는 runner의 INFRA-212(DEFERRED / after launch)와 같은 이야기다.
  • minseo는 9/23에 이미 행사 당일 장애를 경고했고, yuna의 9/28 메시지로 업데이트 당일 MORI가 종료된다는 사실이 확인된다.
  • 로컬 기록은 앱의 삭제 기능으로 지워졌지만 identity.dpapi가 남아 서버에 쌓인 트래픽을 그대로 복호화할 수 있었다. 정적 키 교환이라 전방 비밀성도 없다.
