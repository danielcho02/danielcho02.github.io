획득한 Flag

정답 입력값: 23:47 (KST)

풀이 방법

사내 스마트 금고(VAULT-01) 관리망을 미러링한 PCAP이 주어진다. 분실 신고된 하드웨어 지갑이 금고에서 빠진 시각(KST, HH:MM)을 unlock.py에 넣으면 플래그가 나온다.

0. 전수 대입이 안 되는 이유

flag.lock은 scrypt(n=2^20, r=8)를 30번 연달아 돌린다. 한 후보에 1 GiB 메모리와 약 58초가 든다. 후보는 24×60 = 1,440개라 전부 넣으면 약 23시간이다. 정확한 시각을 먼저 구해야 한다. 검증은 HMAC이라 맞으면 복호화되고 틀리면 실패한다.

1. 신고자와 슬롯 확인

HTTP 요청 대부분은 메뉴·공지·캘린더 같은 일상 트래픽이다. 의미 있는 건 두 건이다.

  • 11-04 09:12:44, POST security.corp.local/api/incidents: 신고자 C, 종류 lost_device. 본문은 “사고 소식을 듣고 금고를 확인했는데 하드웨어 지갑이 사라졌습니다! 11월 2일 퇴근할 때까지는 분명히 있었습니다.”
  • 11-04 09:05:10, GET vault-mgmt.corp.local/api/vault01/slots: slot 1 = D, slot 2 = C, slot 3 = A, slot 4 = B

슬롯 번호와 소유자 알파벳이 일부러 어긋나 있다. C의 지갑은 slot 2다.

2. MQTT에서 이벤트 꺼내기

1883/tcp MQTT PUBLISH가 691건 있다. 슬롯마다 600초 간격으로 상태를 보고하고(vault01/slot/N/state), 이벤트는 vault01/event로 따로 나간다.

up은 부팅 뒤 경과한 밀리초다. 주기 보고는 23:20:00 다음에 06:20:00이 와서 정확히 7시간이 비어 있다. 06:12:31에 {"msg": "link restored", "queued": 4}가 오고 이벤트 4건이 0.05초 안에 한꺼번에 들어온다. 이 네 건의 패킷 시각은 전송 시각일 뿐이고 실제 발생 시각은 up으로 구해야 한다.

3. 업타임을 벽시계로 환산

주기 보고는 큐를 거치지 않고 바로 전송되므로 패킷 epoch − up/1000이 부팅 시각이다. 주기 보고 684건으로 계산하면 35시간 동안 값의 차이가 1 ms 안에 들어온다. 부팅 시각은 epoch 1793486592.512, 2026-11-01 07:43:12 KST다.

up (ms) 실제 시각 (KST) 이벤트
143739487 11-02 23:38:51 door_open, badge 0x3F2A91
143874487 11-02 23:41:06 slot 3 absent (A의 지갑)
144246487 11-02 23:47:18 slot 2 absent (C의 지갑)
144377487 11-02 23:49:29 door_close

C의 지갑은 23:47에 빠졌다.

헷갈리기 쉬운 부분

  • 패킷 시각 06:12:31을 그대로 쓰면 틀린다. queued: 4가 큐에 쌓였던 이벤트임을 알려 준다.
  • 주기 보고에서 slot 2가 absent로 바뀌는 건 06:20:00이다. 링크 복구 뒤 첫 보고일 뿐이다.
  • weight_g는 41.6~42.4 사이에서 흔들리는 센서 지터다. 빠진 슬롯은 0.0으로 떨어져 구분이 분명하다.

획득한 단서

지갑은 두 개가 사라졌다

슬롯 소유자 빠진 시각 (KST) 캡처 종료(11-04 09:20) 상태
slot 3 A 11-02 23:41:06 absent, 0.0 g
slot 2 C 11-02 23:47:18 absent, 0.0 g

한 번 열린 문(23:38:51~23:49:29, 638초) 안에서 A와 C의 지갑이 6분 12초 간격으로 나갔다. 둘 다 끝까지 돌아오지 않았는데 신고한 사람은 C뿐이다. A는 신고하지 않았다.

통신 장애와 배지

  • 주기 보고가 23:20~06:20 정확히 7시간 끊겼고, 문이 열렸다 닫힌 10분 38초가 통째로 이 구간 안에 있다. 의도적 차단일 수 있지만 끊긴 구간의 트래픽이 캡처에 없어 PCAP만으로는 단정하지 못한다.
  • 지갑이 나간 세션은 배지 0x3F2A91로 열렸다. 배지와 사람의 매핑은 이 PCAP에 없다.
  • 11-03 14:10:21에 다른 배지 0x51C0D7로 문이 1분 43초 열렸지만 슬롯 변화는 없다.
  • slot absent 상태가 33시간 넘게 이어졌는데도 아무도 반응하지 않았고, C는 “사고 소식을 듣고” 나서야 금고를 확인했다.

망 구성

이름 주소 역할
intranet.corp.local 10.20.0.30 사내 포털
security.corp.local 10.20.0.20 보안 포털 (사고 신고)
vault-mgmt.corp.local 10.20.0.10 금고 관리 서버, MQTT 브로커
VAULT-01 게이트웨이 10.20.0.50 MQTT 퍼블리셔

직원 PC는 10.20.1.x다. MQTT는 평문이고 인증 흔적이 없다. 금고 장치에는 NTP도 RTC도 없어 up만 보고한다.

다른 문제와의 연결

  • Dead Frame: 금고 문이 닫히고 12분 42초 뒤인 11-03 00:02:11에 출금 WD-20261102-31A0(12 BTC)이 물리 콘솔에서 만들어졌다. 서명자는 A와 C로, 금고에서 나간 두 지갑의 주인과 같다. 이 거래는 보류(hold)됐다. 실제로 12.4 BTC가 나간 11-03 21:17 거래는 B와 D가 서명했다.
  • 네 명(A·B·C·D)은 Dead Frame 멀티시그 서명자와 같다. A는 wallet manager, B는 security researcher, C는 finance manager, D는 security engineer다.
  • Unplugged: 같은 밤 01:55에 ALEX 자택 서재에서 WALLET 라벨 백업 디스크가 반출됐다. 라벨과 시간대가 겹칠 뿐, 금고의 하드웨어 지갑과 같은 자산이라는 증거는 없다.
