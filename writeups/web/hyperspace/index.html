Summary

이미지 업로드 폼이 클라이언트가 보낸 MIME 타입만 검사하고 확장자를 막지 않아 .php 웹셸로 RCE를 얻고, 그 발판에서 내부망을 스캔해 Apache Druid 0.20.0(CVE-2021-25646)을 root로 장악한다. Druid 호스트에 남겨진 자격증명으로 내부 HYPERSPACE 포털에 로그인한 뒤, launch.php의 4자리 PIN 게이트를 브루트포스하면 verify_pin.php가 플래그를 돌려준다.

진입점: http://<target>/index.php

네트워크 지형

  • 172.16.238.10:80 — 공개 웹(업로드 폼). 최초 발판.
  • 172.16.238.11:80 — 내부 HYPERSPACE 발사 관제 포털(로그인 → dashboard/launch).
  • 172.16.238.52:8081,8888 — Apache Druid 0.20.0 콘솔.
  • 172.16.238.1:22 — 게이트웨이.

Solution

Step 1: 업로드 필터 우회 → 웹 컨테이너 RCE

upload.php는 $_FILES['file-upload']['type'](클라이언트 제어)만 화이트리스트 검사하고 원본 확장자를 그대로 유지한다. PNG 매직바이트 뒤에 PHP를 붙이고 type: image/png로 .php를 올리면 data/<md5>.php에서 실행된다. → www-data @ 172.16.238.10.

Step 2: 내부망 피벗 → Druid 발견

웹셸에서 172.16.238.0/24를 스레드 스캔해 .52:8888(Druid 0.20.0 콘솔)을 식별.

Step 3: CVE-2021-25646 → Druid root RCE

Druid 0.20.0은 JavaScript 파서가 비활성이지만, sampler 요청의 parseSpec에 빈 키 객체 "":{"enabled":true}를 주입하면 JavaScriptConfig가 덮어써져 강제 활성화된다. (널리 알려진 PoC의 enableJavaScript 키는 이 빌드에서 동작하지 않고, 실제 키는 enabled였다.) JS 함수에서 Runtime.exec로 명령 실행 → uid=0(root) @ 172.16.238.52.

Druid 호스트 /opt/hyperspace_account.txt:

Step 4: 포털 로그인 → PIN 브루트포스 → 플래그

탈취한 계정으로 172.16.238.11/index.php에 로그인하면 launch.php에 4자리 PIN 입력이 있다. 플래그는 올바른 PIN일 때 verify_pin.php의 JSON 응답에만 존재({"success":true,"flag":"..."}). 레이트리밋·락아웃이 없어 0000–9999 브루트 → PIN 6666.

전체 솔브 스크립트

모든 내부망 접근은 Step 1의 웹셸을 프록시로 사용한다. WEBSHELL에 업로드된 셸 경로를 넣고 실행하면 플래그까지 출력한다.

Notes / 비파괴 원칙

  • .52·.11에는 파일 생성 없이 메모리·HTTP 요청으로만 접근. 발판인 .10의 data/에만 업로드 웹셸이 남음.
  • 서버 가용성을 해치는 공격(파괴·DoS)은 수행하지 않음. PIN 브루트는 4자리 설계 게이트에 대한 의도된 경로.
